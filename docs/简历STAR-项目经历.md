## AI 同人文创作平台（产品经理 / [兼项目负责人]）

**项目时间：** [2026.xx – 2026.xx]　**项目类型：** 独立/团队项目　**状态：** 内测可用（v0.7）

### 一句话

面向同人创作者，搭建「原著结局后续写」AI 工作台：人物深档约束 + 原著检索 + 一致性审查 + 连载存档，并实现多用户内容隔离。

---

### S（Situation）背景

同好使用通用大模型写同人时，普遍存在人物 OOC、偏离原著或补写中间篇、多轮续写丢失前文、多人共用缺乏隐私等问题。市场不缺「能写字的模型」，缺的是**场景化约束与连载工作流**。

### T（Task）任务

负责定义产品方向与需求，设计从「选书/上传 → 创作 → 审查 → 存档续写」的完整闭环，明确权限与成本边界，推动可演示、可内测的版本落地，并沉淀 PRD 与迭代优先级。

### A（Action）行动

1. **场景收敛：** 将产品定位为「只写原著结局之后」，用结局记忆与审查规则禁止中间篇补白，避免做成万能写作工具。  
2. **质量机制：** 设计人物深档（底色/经历/弧光/关系/禁忌/铁律）注入创作；引入独立审查打分，低于阈值自动修订，形成双重保障。  
3. **供给策略：** 规划「上传现准备」：抽候选人物 → 用户勾选深档（1–6）→ 其余简档 → 结局摘要与 RAG 入库；候选不预勾选，控制成本与耗时。  
4. **资产与信任：** 设计公私书库与存档 `owner` 隔离，普通用户互不可见，管理员可排障；内测采用预置账号、不开放注册。  
5. **协作交付：** 输出 PRD（目标/流程/优先级/验收/指标/风险），按 P0–P3 拆里程碑，跟进主路径验收与体验问题（如登录可达性、进度反馈）。

### R（Result）结果

- 跑通内测闭环：**登录 → 选书/上传准备 → 生成章节 → 审查报告 → 存档续写**。  
- 形成可复用的产品方法论：约束系统（深档+结局+RAG+审查）优于单纯调 prompt。  
- 明确数据隔离与公私书库规则，降低多用户场景下的信任风险。  
- 输出完整 PRD 与面试级流程说明，便于评审对齐与后续迭代（改密、合规、公网部署等）。

*量化结果（有数据则替换）：* 例如「准备任务可异步完成并可视化进度；审查分阈值 60；深档上限 6 人；支持 N 本示例书与用户私人上传」等。
