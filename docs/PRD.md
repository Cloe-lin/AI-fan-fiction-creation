## 1. 背景与问题

### 1.1 背景

同人创作者在原著结局之后续写故事时，常依赖通用大模型。通用模型虽能生成文本，但容易出现：

- 人物 OOC（言行、关系、性格偏离原著）
- 胡编原著情节，或回写/补写中间篇章
- 多轮续写后丢失前文与用户剧情走向
- 多用户共用同一作品时，创作内容互相可见，缺乏隐私边界

### 1.2 要解决的问题

在「原著结局之后续写」这一明确场景下，提供一套**可约束、可连载、可隔离**的 AI 创作工作台，而不是开放式聊天框。

### 1.3 产品一句话

> 基于人物深档 + 原著检索 + 一致性审查，帮助用户在原著结局之后创作并连载同人文，且用户之间内容互不可见。

## 2. 目标与非目标

### 2.1 目标（Goals）

| 编号 | 目标 | 验收标准（摘要） |
|------|------|------------------|
| G1 | 用户能基于已入库作品完成「结局后」一章创作 | 登录 → 选书 → 选角 → 设定 → 产出正文 |
| G2 | 降低 OOC 与结局矛盾 | 创作注入深档/结局记忆；审查打分；低分自动修订 |
| G3 | 支持连载 | 自动存档；续写携带前文记忆与用户走向 |
| G4 | 支持用户自助供给新书 | 上传 txt → 抽人 → 深/简档 → 结局摘要 → RAG 入库 |
| G5 | 多用户内容隔离 | 存档按作者可见；私人书库仅本人可见 |

### 2.2 非目标（Non-Goals）本期不做

- 开放公网注册与社交社区（关注、评论广场）
- 正版授权书城、版权清结算
- 移动端原生 App / 微信小程序完整版
- 多模态（配图、语音朗读）
- 实时协作共创同一存档

## 3. 用户与角色

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| 普通用户 | 预置账号 user01–user20 | 选书/上传、续写、只看自己的存档 |
| 管理员 | 预置账号 admin | 公共书库上传、全选深档、查看全部存档（排障/运营） |

**账号策略（现行）**

- 不开放自助注册
- 预置账号 + 初始密码分发（`credentials_initial.txt`，不入库）
- JWT 登录会话

## 4. 核心概念

| 概念 | 定义 |
|------|------|
| 公共书库 | 全员可见、可选的作品集合 |
| 私人书库 | 仅上传者可见的作品 |
| 深档 | 完整多维人物档案，适合主写对象 |
| 简档 | 短版档案，适合配角，降低准备成本 |
| 结局记忆 | 原著结局摘要 + 结局时人物状态，强制「只写之后」 |
| RAG | 按剧情检索原著片段，注入创作上下文 |
| 存档（Series） | 某一用户对某作品的连载系列，含多章 |
| 一致性审查 | 独立模型对正文打分并列出 OOC/设定问题 |

## 5. 用户流程

### 5.1 主流程：创作与连载

```
登录
 → 选择可见作品
 → 新建存档 或 载入「我的存档」
 → 选择参与人物 / 填写剧情设定、基调、篇幅等
 → 系统生成一章（档案+结局+RAG[+前文记忆]）
 → 一致性审查（必要时自动修订）
 → 展示正文、评分、原著参考
 → 自动写入存档
 → 填写下一章走向 → 续写
```

### 5.2 支流程：上传现准备

```
登录
 → 上传 .txt（默认私人书库；管理员可选公共）
 → 系统抽取约 6 名候选人物（不预勾选）
 → 用户勾选 1–6 人做深档，其余简档
 → 异步生成：深/简档 → 结局摘要 → 登记书库 → RAG 入库
 → 准备完成，进入主流程创作
```

### 5.3 异常与边界

| 场景 | 产品行为 |
|------|----------|
| 未登录访问业务接口 | 拒绝，引导登录 |
| 访问他人存档 | 403，不可见、不可续写 |
| 访问他人私人书 | 403，列表不展示 |
| 准备任务失败 | 展示错误；支持重新抽取 / 重试准备 |
| 审查分 &lt; 60 | 自动修订并再审，前端展示报告 |
| 深档人数为 0 或 &gt; 6 | 不允许开始准备 |

## 7. 业务规则（必须遵守）

1. **只写结局之后**：创作与审查均禁止将续写做成原著中间篇章补白。  
2. **深档上限**：单次准备深档最多 6 人，至少 1 人。  
3. **候选不预勾选**：避免默认全选导致成本与耗时失控。  
4. **私人书默认**：普通用户上传默认 `private`；仅管理员可选 `public`。  
5. **存档归属**：新建存档写入当前用户 `owner_id`；无归属旧数据仅管理员可见。  
6. **作品隔离**：人物与 RAG 检索不得跨小说混用设定。

## 8. 信息架构与页面

```
登录页
└─ 工作台
   ├─ 顶栏：品牌 + 当前用户 + 退出
   ├─ 导入小说（可折叠）
   │    入库目标 / 标题 / 上传 / 候选深档 / 进度
   ├─ 创作设定
   │    选书 / 我的存档 / 标题 / 人物 / 接续起点
   │    剧情设定 / 基调 / 视角 / 篇幅 / 备注 / 生成
   └─ 续写正文
        章节导航 / 正文 / 原著参考 / 一致性报告 / 续写下章
```

## 9. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 准备任务异步；前端轮询进度；创作允许分钟级等待并有明确 loading |
| 安全 | 密钥不进仓库；密码哈希存储；JWT；接口鉴权；存档/私人书权限校验 |
| 可用性 | 错误可读；登录失败提示连接问题；准备失败可重试 |
| 兼容 | 现代桌面浏览器；通过 `http://host:8010/` 访问 |
| 可运维 | 单机可运行；数据目录可备份（`auth.db`、novels、stories、chroma） |
| 部署约束 | 不适配纯 Vercel Serverless 全栈；前端可静态托管，后端需持久磁盘 |

## 11. 成功指标

### 11.1 北星（建议）

**有存档用户的 7 日续写率**（完成第 1 章后 7 日内至少续写 1 次的比例）

### 11.2 过程指标

| 指标 | 含义 |
|------|------|
| 首章完成率 | 登录用户中完成至少一章生成的比例 |
| 准备成功率 | 上传任务最终 COMPLETED 的比例 |
| 准备耗时 P50/P90 | 从开始准备到完成 |
| 审查均分 | 输出章节一致性分数均值 |
| 自动修订触发率 | 分数 &lt; 60 的章节占比 |
| 每章成本 | 平均 LLM 调用次数 / token |

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 版权与 UGC | 法律与平台合规 | 私人默认；内测账号；上线补协议与审核 |
| 生成质量不稳 | 信任下降 | 深档 + 审查 + 展示分数；支持重写 |
| LLM 成本与耗时 | 体验与预算 | 深/简分层；异步准备；监控调用量 |
| 单机文件存储 | 难水平扩展 | 小流量可接受；规模化再迁对象存储/DB |
| 预期偏差 | 「以为是社区」 | 明确定位为创作工具，非社交平台 |
