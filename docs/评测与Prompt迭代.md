# 评测标准 · 评测集 · 反馈驱动 Prompt 迭代

适用产品：AI 同人文平台（结局后续写）  
目标：把「感觉不好」变成可回归、可对比、可上线的策略迭代。

---

## 一、评测标准（什么叫好）

### 1.1 总分与通过线

| 项目 | 定义 |
|------|------|
| 自动分 | 审查模型输出 `score` ∈ [0, 100] |
| 通过线（现行） | `passed=true` 且建议关注 `score ≥ 60`；`<60` 触发自动修订 |
| 人工分（抽检） | 1–5 分，见下表；**黄金集以人工分为准做标定** |

> 自动分用于线上闸门；黄金集需定期用人工分校准自动分是否漂移。

### 1.2 分维度标准（人工评测主表）

每条样例按 5 个维度打分（1–5），再给总体结论。

| 维度 | 1 分（差） | 3 分（可接受） | 5 分（好） | 一票否决 |
|------|------------|----------------|------------|----------|
| D1 人物一致性 | 明显 OOC、说话做事不像此人 | 大体像，有小瑕疵 | 言行/关系高度符合深档 | 触碰 `taboos` |
| D2 结局合规 | 改写结局、复活不该复活的设定等 | 基本接结局，偶有模糊 | 明确接在结局之后 | **写成中间篇补白** |
| D3 用户意图 | 完全跑题 | 部分贴合设定 | 严格按用户剧情推进 | — |
| D4 连载连贯 | 与上章矛盾/失忆 | 能接上但生硬 | 自然承接结尾与未收束线索 | — |
| D5 可读性 | 不通顺、流水账 | 可读 | 有画面感、对话自然 | 严重格式崩坏 |

**人工总分建议：**  
`总分 = D1×0.3 + D2×0.25 + D3×0.2 + D4×0.15 + D5×0.1`（续写样例含 D4；首章 D4 可记 N/A，权重并入 D1/D3）

**发布门禁（建议）：**

| 集合 | 门禁 |
|------|------|
| 黄金集 | 人工均分 ≥ 3.5；一票否决项 = 0；中间篇补白 = 0 |
| 挑战集 | 一票否决拦截率 ≥ 90%（该判 error 的必须判出） |
| 线上抽样 | 周均人工分不下降；OOC 类反馈占比不升 |

### 1.3 与系统 issue_type 对齐

| 评测维度 | 系统 `issue_type` | severity 建议 |
|----------|-------------------|---------------|
| D1 | `ooc` / `tone_mismatch` | warning / error（触禁忌→error） |
| D2 | `canon_violation` / `mid_chapter_fill` | error |
| D3 | `direction_mismatch` | warning / error |
| D4 | （可扩展 `continuity_break`） | warning |
| D5 | （人工为主） | — |

## 二、评测集怎么构建

### 2.1 三类集合

| 类型 | 规模建议 | 用途 | 更新频率 |
|------|----------|------|----------|
| **黄金集 Gold** | 20～50 条 | 每次改 Prompt/模型必跑回归 | 月度微调，核心不动 |
| **挑战集 Challenge** | 15～30 条 | 测边界与攻击（诱导中间篇、强 OOC） | 随 badcase 增加 |
| **线上集 Online** | 每周 20～50 条抽样 | 反映真实分布 | 周更 |

### 2.2 单条样例字段（评测集 Schema）

| 字段 | 说明 |
|------|------|
| case_id | 如 `GOLD-MDZS-001` |
| set_type | gold / challenge / online |
| novel_id | 作品 ID |
| novel_title | 作品名 |
| characters | 人物 ID 列表 |
| chapter_type | first / continue |
| user_scenario | 用户剧情设定（输入） |
| tone / length | 可选 |
| prior_context | 续写时：上章摘要/结尾要点 |
| must_have | 必须出现的约束（人设/情节） |
| must_not | 禁止项（中间篇、禁忌等） |
| expect_auto_score_min | 期望自动分下限（可选） |
| expect_block | 是否期望被审查卡住 |
| human_score | 人工总分（标定后填） |
| notes | 备注 |

完整表见：`评测集-扩展版.csv`（推荐，约 50 条，含说明见 `评测集说明.md`）  
跑分模板：`评测集-跑分结果模板.csv`  
旧版精简：`评测集-黄金与挑战.csv`

### 2.3 构建步骤（可执行）

1. **定书定人**：先选 1～2 本熟悉原著（如魔道、实用主义者）  
2. **写 20 条正常设定**（黄金）：覆盖温暖/冲突/多人互动/续写  
3. **写 10 条挑战**：诱导写观音庙之前、故意让角色干禁忌事、设定与结局矛盾  
4. **跑现行系统**，记下自动分与 issues  
5. **人工盲评** 打 D1–D5，标定自动分是否可信  
6. **冻结黄金集版本** `evalset_v1`；之后只增不乱改核心条

## 三、根据用户反馈优化 Prompt（闭环）

### 3.1 反馈从哪来

| 来源 | 信号 | 如何结构化 |
|------|------|------------|
| 审查报告 | score、issue_type | 直接入库统计 |
| 用户行为 | 同一设定反复重写、放弃续写 | 记「重写率」「续写流失」 |
| 显式反馈 | 「不像某某」「写成前文了」 | 标签：ooc / mid_chapter / direction… |
| 准备环节 | 深档字段乱、解析失败 | 归到 profile_prompt 版本 |

### 3.2 周迭代节奏（建议）

```
周一  汇总上周：issue 分布、重写率、人工抽检 20 条
周二  归因：是 Prompt / 档案质量 / RAG / 模型本身？
周三  改 Prompt（只改一处主因）→ 填「变更单」
周四  跑黄金集 + 相关挑战集 → 对比表
周五  达标则上线；不达标回滚；同步 badcase 进挑战集
```

### 3.3 归因决策树（避免乱改）

| 现象 | 先查 | 优先动作 |
|------|------|----------|
| 多人 OOC | 深档是否注入、禁忌是否进审查 | 加强创作 Prompt 中禁忌/关系段落；补档案 |
| 总写中间篇 | 审查是否标出 mid_chapter_fill | 加硬约束 + few-shot 反例；提高该类 severity |
| 文对但跑题 | direction_mismatch 是否出现 | 创作侧加重「必须推进用户设定」 |
| 续写断层 | 记忆是否注入 | 工程检查 memory；Prompt 强调承接上章结尾 |
| 分数虚高/虚低 | 与人工黄金集对比 | 校准审查 Prompt，而不是只改创作 |

**原则：一次迭代只动一类 Prompt（创作 / 审查 / 修订 / 深档），否则无法归因。**

### 3.4 Prompt 变更单（复制即用）

```text
【Prompt 变更单】
版本号：prompt_create_v1.3（或 review_v1.2）
负责人：
日期：
关联反馈：
  - 数据：上周 mid_chapter_fill 占比 12% → 目标 <5%
  - badcase：CASE-xxx，用户反馈「写成求学时期了」

改动前问题：
改动内容（摘要）：
  - 在系统提示增加：……
  - 在审查重点增加：……
改动范围：□创作 □审查 □修订 □深档
评测对比：
  - 黄金集均分：x.x → y.y
  - 一票否决数：a → b
  - 挑战集拦截率：c% → d%
结论：□上线 □回滚 □再改一版
```

模板文件：`Prompt变更单-模板.md`

### 3.5 本项目可优先改的 Prompt 杠杆

| 杠杆 | 文件/位置 | 常见反馈 |
|------|-----------|----------|
| 创作系统提示 | `story_generator.build_system_prompt` | OOC、补中间篇 |
| 创作用户提示 | `_build_user_prompt` | 偏离设定、忽略结局 |
| 审查提示 | `_check_consistency` | 漏检、分数不准 |
| 修订提示 | `_revise` | 改完仍跑题或改崩文风 |
| 深档生成 | `prep_service._llm_deep_profile` | 档案空泛、字段类型错 |

## 四、最小落地清单（本周就能做）

1. 用 `评测集-扩展版.csv`（或精简版）按需改设定  
2. 用 `评测集-跑分结果模板.csv` 记录自动分与人工分  
3. 人工评至少 10 条黄金样例，看自动分是否同向  
4. 选 1 个最高频问题，开一张变更单，只改审查或创作 Prompt 一处  
5. 重跑黄金集 + 挑战集，写进对照表  

面试时可说：  
「我不是凭感觉改 Prompt，而是用黄金集回归 + 反馈标签归因 + 变更单版本管理。」

## 五、指标看板（产品周报用）

| 指标 | 计算 | 健康方向 |
|------|------|----------|
| 审查均分 | 章节 score 平均 | ↑ |
| 修订触发率 | score&lt;60 占比 | 适度↓（降太低可能审查变松） |
| OOC issue 占比 | ooc / 总 issue | ↓ |
| 中间篇命中率 | mid_chapter_fill 出现率 | ↓→0 |
| 设定偏离率 | direction_mismatch | ↓ |
| 同设定重写率 | 同一用户短时间重复 create | ↓ |
| 黄金集通过率 | 达门禁的 case 比例 | ≥ 90% |
