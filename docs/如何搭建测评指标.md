# 如何搭建测评指标并测试模型效果

面向本项目（同人续写）与 AIPM 面试口径。  
配套文件：`评测与Prompt迭代.md`、`评测集-扩展版.csv`、`评测集-跑分结果模板.csv`

---

## 一、先分清：你在测什么

同人产品至少有 **两层模型效果**，指标不要混在一起：

| 层级 | 测什么 | 典型模型 | 好不好看什么 |
|------|--------|----------|--------------|
| **创作模型** | 写出的正文质量 | `LLM_MODEL` | 人设、结局合规、贴设定、可读、连载连贯 |
| **审查模型** | 质检准不准 | `LLM_REVIEW_MODEL` | 该拦的拦住、不该杀的别误杀 |
| （可选）**修订模型** | 低分后能否修好 | 同创作或审查链路 | 修订后分数↑、问题消失 |
| （可选）**RAG** | 检索是否有用 | Embedding | 相关度、是否帮到创作 |

**原则：**  
- 换创作模型 → 主要看黄金集人工分 / 自动分  
- 换审查模型或审查 Prompt → 主要看挑战集拦截率 + 黄金集误杀率  

---

## 二、测评指标体系怎么搭（推荐三层）

### 第 1 层：质量指标（核心）

| 指标 | 定义 | 怎么算 | 健康方向 |
|------|------|--------|----------|
| 人工均分 | D1–D5 加权平均 | 见评测标准 | ≥ 3.5（黄金集） |
| 一票否决率 | 触禁忌 / 中间篇补白 | 人工或自动 issue | 黄金集 → 0 |
| 自动审查均分 | `consistency_report.score` | 接口返回 | ↑（需与人工校准） |
| 修订触发率 | score &lt; 60 占比 | 日志/跑分表 | 观察项：过高=创作差，过低=审查松 |
| OOC 占比 | `issue_type=ooc` 次数/总章节 | 统计 | ↓ |
| 中间篇漏检率 | 挑战集里应拦未拦 | 挑战集 | ↓ → 0 |
| 设定偏离率 | `direction_mismatch` | 统计 | ↓ |

### 第 2 层：任务成功率（系统效果）

| 指标 | 定义 | 说明 |
|------|------|------|
| 黄金集通过率 | 达门禁的 case 比例 | 换模/改 Prompt 的主门禁 |
| 挑战集拦截率 | `expect_block=true` 且确实被拦 | ≥ 90% |
| 首章生成成功率 | API 成功返回占比 | 工程稳定性 |
| 准备任务完成率 | prep COMPLETED | 供给侧 |

### 第 3 层：体验与成本（产品效果）

| 指标 | 定义 | 说明 |
|------|------|------|
| 同设定重写率 | 短时间重复生成 | 用户不满意的代理指标 |
| 7 日续写率 | 有存档用户续写占比 | 北极星候选 |
| 每章耗时 / token | 延迟与费用 | 效果好但贵也要权衡 |

面试一句话：  
「质量看人设与合规，闸门看通过率/拦截率，产品看续写与重写，成本看 token。」

## 三、测试模型效果的标准流程

```
① 固定评测集（输入不变）
② 固定其余变量（Prompt 版本 / RAG 开关 / 温度）
③ 只改「一个」自变量：模型 或 Prompt
④ 批量跑创作+审查，记录分数与 issues
⑤ 人工抽检标定（尤其黄金集）
⑥ 对比基线，决定上线/回滚
```

### 3.1 准备

1. 评测集：用 `docs/评测集-扩展版.csv`（已有约 49 条）  
2. 结果表：用 `docs/评测集-跑分结果模板.csv`  
3. 记下基线：`prompt_version` + `model_name` + 日期  

### 3.2 跑法（两种）

**A. 手工抽测（先做 10 条）**

1. 登录系统，按 CSV 的 `novel_id` / 人物 / `user_scenario` 生成  
2. 把返回的 `score`、`issues` 填进结果表  
3. 自己按 D1–D5 打人工分  

**B. 半自动（推荐后续做）**

- 脚本读 CSV → 调 `POST /api/stories/create` → 写回 `auto_score`  
- 续写 case 需先有存档或构造 `prior_context`（挑战续写可只测首章+人工）  

### 3.3 对比实验设计（测模型必须这样）

| 实验 | 固定 | 变化 | 看什么 |
|------|------|------|--------|
| 换创作模型 | 审查模型、Prompt、评测集 | `LLM_MODEL` | 黄金集均分↑？挑战误放↑？ |
| 换审查模型 | 创作模型、Prompt、评测集 | `LLM_REVIEW_MODEL` | 拦截率↑且黄金误杀不升 |
| 改审查 Prompt | 模型、评测集 | 审查提示词 | 中间篇漏检↓ |
| 关/开 RAG | 模型、Prompt | RAG | 均分与「胡编感」是否改善 |

**一次只改一个变量**，否则不知道是谁的功劳。

### 3.4 门禁（能不能换模上线）

| 集合 | 通过条件 |
|------|----------|
| 黄金集 | 人工均分 ≥ 3.5；一票否决 = 0；中间篇 = 0 |
| 挑战集 | 应拦截拦截率 ≥ 90% |
| 相对基线 | 黄金均分不下降超过 0.2；成本可接受 |

不达标 → 回滚模型或回滚 Prompt。

## 四、人工分怎么打（操作定义）

对每条生成正文：

1. **先看一票否决**：有没有中间篇、触禁忌 → 有则整条 Fail  
2. **再打 D1–D5（1–5）**  
3. **总分**（首章可不计 D4）：  
   `0.3×D1 + 0.25×D2 + 0.2×D3 + 0.15×D4 + 0.1×D5`  
4. 与自动分对比：若经常「自动高、人工低」→ 审查模型偏松，优先改审查  

---

## 五、审查模型「准不准」怎么单独测

挑战集每条有 `expect_block=true/false`：

| 实际情况 \ 期望 | 应拦截 | 不应拦截 |
|-----------------|--------|----------|
| 系统拦了 | ✅ True Positive | ❌ False Positive（误杀） |
| 系统没拦 | ❌ False Negative（漏检） | ✅ True Negative |

关注：

- **召回（漏检少）**：中间篇、严重 OOC 不能漏  
- **精确（误杀少）**：正常黄金集别被乱杀  

漏检多 → 加强审查 Prompt / 换更强审查模  
误杀多 → 审查过严或创作其实合格，分开看样例

## 六、最小可执行周计划

| 天 | 动作 |
|----|------|
| Day 1 | 冻结评测集版本；跑基线 10 条黄金 + 5 条挑战 |
| Day 2 | 人工打完这 15 条；记下基线指标 |
| Day 3 | 换一个创作模型或改一处 Prompt，重跑同 15 条 |
| Day 4 | 对比表；写结论（上线/回滚） |
| Day 5 | 把新 badcase 补进挑战集 |

---

## 七、结果怎么汇报（给老板/面试）

```text
实验：创作模型 A → B（审查与 Prompt 不变）
集合：黄金 20 + 挑战 10
结果：
  黄金人工均分 3.4 → 3.7
  挑战拦截率 80% → 90%
  修订触发率 35% → 22%
  预估成本 +15%
结论：质量提升可接受成本，建议灰度上线 B
```

## 九、面试 30 秒版

「我会先建黄金集和挑战集，定义人设、结局合规、意图、连贯、可读五维指标，再加一票否决。测模型时固定评测集和 Prompt，只换模型，对比通过率和拦截率，并用人工分校准自动审查分。达标才上线，不达标回滚——用评测闭环代替体感调参。」
